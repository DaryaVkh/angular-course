# Расширенные знания

## Navigation Lifecycle

Упрощенно процесс navigation выглядит так:

```
NavigationStart
      │
      ▼
URL recognition
      │
      ▼
Guards
      │
      ▼
Resolvers
      │
      ▼
Component activation
      │
      ▼
NavigationEnd
```

И иногда при определенных условиях бывает `NavigationCancel` и `NavigationError`.

### NavigationStart

Срабатывает в самый первый момент, когда пользователь или код инициирует переход по новому адресу, еще до запуска guards и загрузки скриптов.

Для чего используется:
- Глобальные индикаторы загрузки: мгновенное отображение прогресс-бара или спиннера, пока скачиваются ленивые бандлы или выполняются резолверы.
- Сброс UI-состояний: закрытие открытых модальных окон, выпадающих списков или мобильного бокового меню перед переходом.
- Прерывание фоновых задач: отмена активных HTTP-запросов (AbortController / takeUntil), относящихся к предыдущей странице.
- Определение источника навигации: свойство event.navigationTrigger позволяет узнать, как был вызван переход — программно ('imperative') или кнопками браузера «Назад/Вперед» ('popstate') .

### NavigationCancel

Срабатывает, когда переход был намеренно отменен логикой приложения . Чаще всего это происходит, если Guard (canActivate, canDeactivate, canMatch) вернул false или UrlTree для редиректа.

Для чего используется:
- Скрытие индикатора загрузки: остановка прогресс-бара или спиннера, запущенного в NavigationStart (иначе он зависнет на экране).
- Уведомления пользователя (Toast / Snackbars): вывод предупреждения, если переход отменен.
- Свойство event.reason: диагностика причины отмены (например, логирование, какой именно гард или условие заблокировали навигацию).

### NavigationError

Срабатывает при возникновении непредвиденного сбоя в процессе навигации. Например, сетевая ошибка при скачивании ленивого чанка (Failed to fetch dynamically imported module), исключение внутри Resolver или синтаксическая ошибка.

Для чего используется:
- Отказоустойчивость при деплое (Chunk Load Error): автоматическая перезагрузка страницы (window.location.reload()), если после выкатки новой версии старый ленивый JS-чанк был удален с сервера.
- Системы мониторинга и телеметрии: отправка стека ошибок в сервисы логирования (Sentry, Datadog) через свойство event.error.
- Отображение fallback-экрана: перенаправление пользователя на общую страницу ошибки (/500) или показ баннера о потере интернет-соединения.

### NavigationEnd

Финальное событие успешного жизненного цикла Angular Router, которое сигнализирует о том, что маршрут полностью активирован, а компонент отрисован.

В отличие от NavigationStart или событий отмены, в момент появления NavigationEnd URL в адресной строке уже гарантированно обновился и все асинхронные резолверы и гарды завершили свою работу.

Для чего используется:
- Сквозная веб-аналитика 
- Доступность, например, автофокус на главном интерактивном элементе
- Управление скроллом
- Скрытие глобальных лоадеров

## Route-level providers

Routes могут иметь собственные providers. Это позволяет создавать route-scoped dependency injection.

```ts
{
  path: 'admin',
  providers: [
    AdminService,
  ],
  loadChildren: () => import('./admin.routes').then(({routes}) => routes),
}
```

## Auxiliary / named outlets

Angular Router поддерживает несколько outlets одновременно:

```html
<router-outlet />

<router-outlet name="sidebar" />
```

Тогда можно управлять primary outlet и sidebar outlet одновременно. Это уже более продвинутая возможность. Она может быть полезна, например, когда main и sidebar имеют независимые navigation state.

## queryParamsHandling

`queryParamsHandling` — это свойство Angular Router, определяющее, как поступать с уже существующими в URL query-параметрами при переходе на новый маршрут. По умолчанию Angular полностью удаляет старые параметры строки запроса при любой навигации; `queryParamsHandling` позволяет сохранить их или точечно обновить.

Свойство принимает три строковых значения:
- '' (пустая строка / значение по умолчанию): полностью очищает текущие query-параметры и заменяет их новыми, если они были переданы.
- 'merge': объединяет текущие параметры URL с новым набором. Одинаковые ключи обновляются новыми значениями, отсутствующие в новом наборе — сохраняются, а передача null или undefined удаляет конкретный ключ.
- 'preserve': полностью сохраняет текущие query-параметры без изменений. Любые новые параметры, переданные одновременно в queryParams, будут проигнорированы.

Пример:

При текущем URL `/catalog?category=books&author=tolstoy` и клике на ссылку:

```html
<a [routerLink]="['/catalog']" 
   [queryParams]="{ page: 2 }" 
   queryParamsHandling="merge">
   Страница 2
</a>
```
Итоговый URL будет `/catalog?category=books&author=tolstoy&page=2`.

Программный вариант:

```ts
this.router.navigate(['/catalog'], {
  queryParams: { page: 2 },
  queryParamsHandling: 'merge'
});
```

## Navigation extras

Навигация может содержать дополнительные настройки. Некоторые из них очень полезны.

### replaceUrl

Обычно navigate(...) создаёт новую запись в browser history.

```
/
↓
/users
↓
/users/42
```

A `replaceUrl: true` заменяет текущую history entry.

Это может быть полезно, например, при переходе `/login` -> `/home`, чтобы back не возвращал пользователя на логин.

### skipLocationChange

Флаг `skipLocationChange: true` выполняет навигацию и монтирует новый компонент в `<router-outlet>`, не изменяя при этом URL в адресной строке браузера и не добавляя новую запись в историю переходов. Это позволяет «тихо» переключить отображаемый экран внутри Single Page Application, оставляя для пользователя и браузера иллюзию того, что он находится на прежнем адресе.

Это может быть полезно в следующих случаях:
- Обработка динамических ошибок: без флага: редирект на `/404` заменит строку браузера на `site.com/404`. Пользователь потеряет введенный адрес и не сможет понять, где он опечатался.
- Многошаговые формы и степперы: если регистрация или оформление заказа состоит из 4 шагов, засорять историю браузера отдельными адресами (`/checkout/step-1`, `/checkout/step-2`) часто нежелательно.
- Принудительная перезагрузка текущего маршрута (Component Reload)
- Скрытие технических экранов и промежуточных состояний

## Location

Angular также предоставляет `Location` для работы с browser URL/history на более низком уровне.

Например:
```ts
const location = inject(Location);

location.back();
```

Но для обычной навигации лучше использовать `Router`, а не напрямую манипулировать URL.

## Почему не стоит делать window.location.href

Можно написать `window.location.href = '/users';`. Но это уже браузерная навигация, а не нормальная Angular Router navigation. Она может привести к полной перезагрузке приложения.

В Angular обычно `router.navigate(['/users']);`
