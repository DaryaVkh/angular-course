# Практикум по RxJS: от разбора багов до реактивных UI-паттернов

В этой папке собраны **4 практических задания** к модулю по RxJS. Каждая задача моделирует реальную продуктовую проблему, с которой фронтенд-разработчики сталкиваются в продакшене: гонки данных при открытии модалок, «умирающие» после первой ошибки HTTP-стримы, ложноположительные результаты пакетного удаления и защита опасных действий от случайного клика.

---

## Маршрут прохождения

Рекомендуем проходить задания по порядку — от базового управления жизненным циклом потока к композиции сложных событий DOM и времени:

| № | Задание | Сложность | Время | Продуктовый сценарий | Ключевые темы лекции | Команда запуска |
| :-: | :--- | :---: | :---: | :--- | :--- | :--- |
| **1** | [**Гонка при загрузке данных**](./race-condition/README.md) | 🟢 Базовый | 20–30 мин | Модальное окно открывается раньше, чем пришёл ответ от сервера, либо плодит лишние HTTP-запросы | Cold vs Hot, кэширование потока, мультикастинг (`shareReplay`, `take`) | `npm run serve:rxjs-race-condition` |
| **2** | [**Живучесть потока: `catchError`**](./catch-error/README.md) | 🟢 Базовый | 25–35 мин | После одной ошибки `404` кнопка отправки формы перестаёт реагировать на новые нажатия | Контракт Observable, терминальность `error`, изоляция ошибки во внутреннем потоке | `npm run serve:rxjs-catch-error` |
| **3** | [**Ловушка при объединении потоков**](./high-order-operator-bug/README.md) | 🟠 Средний | 30–40 мин | Пакетное удаление записей рапортует «Успешно!», хотя часть операций завершилась сбоем | Агрегация потоков (`forkJoin`, `merge`, `reduce`), ожидание всех результатов | `npm run serve:rxjs-high-order-operator-bug` |
| **4** | [**Кнопка с удержанием (Hold-to-Action)**](./hold-to-save-button/README.md) | 🟠 Средний | 40–60 мин | Защита критического действия (удаление / сохранение) через удержание кнопки с прогресс-баром | `fromEvent`, `interval`, `switchMap`, `takeUntil`, композиция DOM-событий и Signals | `npm run serve:rxjs-hold-to-save-button` |

## Как устроено каждое задание

Мы оформили задачи так, чтобы вам было интересно разбираться в сути происходящего, а не действовать по шаблону:

1. **Продуктовый контекст и симптомы** — зачем эта задача нужна в реальном приложении и какую боль пользователя мы лечим.
2. **Мраморные схемы (Marble Diagrams)** — наглядная визуализация того, как события текут во времени **сейчас (с багом)** и **как должны течь (после решения)**.
3. **Интерактивный стенд в браузере** — в каждом приложении есть визуальные индикаторы состояния потока, счётчики сетевых вызовов и журнал событий, чтобы вы видели работу своего кода прямо на экране.
4. **Пошаговый маршрут (`Шаг 1` → `Шаг N`)** — последовательные этапы решения: от исправления основного бага до архитектурной полировки.
5. **Задания со звёздочкой (`*`)** — дополнительные продуктовые требования для тех, кто хочет прокачаться глубже.
6. **Подсказки под спойлером и автотесты** — если застряли, можно открыть подсказку нужного уровня, а после решения — прогнать автоматические тесты и свериться с чек-листом.

```
┌─────────────────────┐     ┌──────────────────────┐     ┌──────────────────────┐     ┌─────────────────────┐
│ 1. Запусти стенд    │ ──► │ 2. Воспроизведи баг  │ ──► │ 3. Изучи мраморную   │ ──► │ 4. Пройди по шагам  │
│    и открой UI      │     │    глазами в браузере│     │    схему в README    │     │    и проверь тесты  │
└─────────────────────┘     └──────────────────────┘     └──────────────────────┘     └─────────────────────┘
```

## Быстрый старт

Все команды выполняются из **корня репозитория**.

### 1. Установка зависимостей (один раз)

```bash
npm install
```

### 2. Запуск нужного задания в браузере

```bash
# Задача 1: Гонка при загрузке данных
npm run serve:rxjs-race-condition

# Задача 2: Обработка ошибок catchError
npm run serve:rxjs-catch-error

# Задача 3: Ошибка при объединении потоков
npm run serve:rxjs-high-order-operator-bug

# Задача 4: Удержание кнопки (Hold-to-Save)
npm run serve:rxjs-hold-to-save-button
```

После запуска откройте `http://localhost:4200`.

### 3. Запуск автотестов для самопроверки

Для каждой задачи подготовлены unit-тесты на Jest (а для первой задачи — дополнительно компонентный тест Cypress):

```bash
# Проверка задачи 1 (Jest)
npx jest -c lessons/rxjs/tasks/race-condition/jest.config.ts

# Проверка задачи 2 (Jest)
npx jest -c lessons/rxjs/tasks/catch-error/jest.config.ts

# Проверка задачи 3 (Jest)
npx jest -c lessons/rxjs/tasks/high-order-operator-bug/jest.config.ts

# Проверка задачи 4 (Jest)
npx jest -c lessons/rxjs/tasks/hold-to-save-button/jest.config.ts
```
