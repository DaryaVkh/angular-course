## Суть задания

Вы разрабатываете панель администрирования каталога, где модератор может одной кнопкой удалить все записи выбранной категории (`food`, `sport`, `book`).

Удаление каждой отдельной записи — это отдельный асинхронный вызов `deleteOneTopic(id): Observable<boolean>`, который возвращает:
- `of(true)` — если запись успешно удалена;
- `of(false)` — если запись защищена от удаления или произошёл сбой (в нашей базе запись `#6 (food)` намеренно заблокирована и всегда возвращает `of(false)`).

Сейчас при нажатии на **Delete Food** запись `#5` удаляется, запись `#6` остаётся в списке, но интерфейс радостно выводит зелёную плашку: **`All food have been deleted`**!

Ваша задача — разобраться, почему комбинация операторов в `AppService.deleteOldTopics()` даёт ложноположительный ответ, и исправить логику агрегации потоков.

## Схема проблемы и целевого поведения

### ❌ Как работает сейчас (`merge` + начальный `of(true)` + `take(1)`)

Посмотрите на текущую реализацию `deleteOldTopics` в `src/app/app.service.ts`:

```ts
infoByType
  .map((t) => this.dbService.deleteOneTopic(t.id))
  .reduce((acc, curr) => merge(acc, curr), of(true))
```

Оператор `merge` не сворачивает значения в одно — он просто **сливает все эмиты в одну общую дорожку по очереди**. А компонент `ButtonDeleteComponent` подписывается на этот поток с оператором `.pipe(take(1))`:

```
Начальный аккумулятор:  of(true)      ──(true)|
Удаление id=5 (food):   delete(5)             ──(true)|
Удаление id=6 (food):   delete(6)                     ──(false)|
                                          │
merge(acc, curr):       ──(true)──────────(true)────────(false)|
                            │
Компонент с take(1):    ──(true)|  ◄── Подписка закрылась на самом первом значении!
                            │
UI-сообщение:           "All food have been deleted" 💥 ЛОЖНЫЙ УСПЕХ!
```

Вдобавок из-за того, что `take(1)` мгновенно отписывается после первого же `true` из стартового `of(true)`, при асинхронных запросах остальные потоки в `merge` вообще могли бы быть отменены до выполнения!

### ✅ Как должно работать (ожидание всех потоков и свертка результата)

Итоговый поток должен дождаться завершения **всех** операций удаления выбранной категории и выдать **ровно одно** булево значение:
- `true` — если **каждая** операция вернула `true` (или если записей этой категории не было);
- `false` — если **хотя бы одна** операция вернула `false`.

```
Удаление id=5 (food):   ────(true)|
Удаление id=6 (food):   ────────(false)|
                                   │
Агрегатор + проверка:   ───────────┴──► (every === true ? false)|
                                                │
UI-сообщение:           "Error: deletion of some food failed" ✅ ЧЕСТНЫЙ РЕЗУЛЬТАТ
```

### Шаг 3 (`*`). Ленивое удаление при подписке

Обратите внимание на тонкий архитектурный момент в `LocalDBService.deleteOneTopic(id)`:

```ts
deleteOneTopic = (id: number) => {
  if (id === 6) {
    return of(false);
  }
  this.deleteOne(id); // ⚠️ Вызывается синхронно в момент вызова функции, ещё ДО .subscribe()!
  return of(true);
};
```

В реальном RxJS-коде побочные эффекты не должны происходить в момент конструирования потока (`map(t => this.dbService.deleteOneTopic(t.id))`) — они должны выполняться **только в момент подписки** (Cold Observable).

Подумайте, как с помощью оператора `defer` в `LocalDBService` сделать `deleteOneTopic` по-настоящему ленивым, чтобы вызов `service.deleteOldTopics('book')` без `.subscribe()` не удалял записи из базы.

## Подсказки

<details>
  <summary>💡 Подсказка 1 — Почему merge здесь не подходит?</summary>

`merge(obs1$, obs2$)` выдаёт каждое значение по отдельности в тот момент, когда оно появляется в любом из потоков. А нам нужно дождаться окончания **всех** потоков и получить их результаты вместе, чтобы проверить условие «все равны `true`».
</details>

<details>
  <summary>💡 Подсказка 2 — Какие операторы умеют собирать все результаты вместе?</summary>

Есть два классических пути в RxJS:
1. **Через оператор комбинирования завершающихся потоков (`forkJoin`):**
   принимает массив `Observable<boolean>[]` и после завершения всех потоков выдаёт один массив `boolean[]`. Дальше его легко преобразовать через `map((results) => ...)`.
2. **Через оператор свёртки потока (`reduce` из `rxjs`, не путать с `Array.prototype.reduce`):**
   если слить потоки в один и применить pipe-оператор `reduce((acc, curr) => acc && curr, true)`, он подождёт `complete` всех значений и выдаст одно финальное булево значение.
</details>
