# Задача 4. Кнопка с удержанием (Hold-to-Action Directive)

🟠 **Уровень:** средний · ⏱ **Время:** 40–60 минут · 📖 **Лекция:** [Разделы 3–6 (`fromEvent`, `interval`, `switchMap`, `takeUntil`)](../../lecture/RxJS%20%E2%80%94%20%D0%9B%D0%B5%D0%BA%D1%86%D0%B8%D1%8F%20%28Markdown%29.md)

---

## Суть задания

В интерфейсах для необратимых или дорогих операций — удаления аккаунта, отправки крупного платежа, сброса настроек сервера — вместо раздражающего модального окна *«Вы уверены? Да / Нет»* часто применяют паттерн **Hold-to-Confirm** (кнопка с удержанием).

Пока пользователь зажимает кнопку, полоса прогресса плавно заполняется (или убывает). Если отпустить кнопку или увести с неё курсор хотя бы на мгновение раньше срока — действие отменяется, а прогресс сбрасывается. Если продержать до конца — действие подтверждается.

Попытка написать такую логику императивно на `setInterval` и `clearInterval` быстро превращается в клубок флагов и утечек таймеров. На RxJS вся эта механика собирается в один декларативный конвейер внутри переиспользуемой директивы `[appHoldable]`.

Из корня репозитория выполните:

## Схема работы потока

### Сценарий 1: Раннее отпускание кнопки (отмена)

```
start$ (pointerdown):  ──(down)──────────────────────────────────────►
cancel$ (up / leave):  ────────────────────────(up)──────────────────►
                            │                   │
inner interval:             └──►──(10%)──(20%)──✕ (прерван через takeUntil)
                                                │
holdProgress:          ──(0%)────(10%)──(20%)──(0%)──────────────────►
holdTimeEnd:           ──────────────────────────────────────────────► (не сработал!)
```

### Сценарий 2: Полное удержание до конца (`holdTime = 2000 мс`)

```
start$ (pointerdown):  ──(down)──────────────────────────────────────►
cancel$ (up / leave):  ────────────────────────────────────────(up)──►
                            │
inner interval:             └──►──(25%)──(50%)──(75%)──(100%)| (завершился сам)
                                                         │
holdProgress:          ──(0%)────(25%)──(50%)──(75%)───(100%)────────►
holdTimeEnd:           ────────────────────────────────(emit!)───────► ✅ Save it!
```

### Контракт директивы `HoldableDirective`

В `src/app/holdable.directive.ts` уже объявлены:
- `readonly holdTime = input<number>(1000)` — время удержания в мс;
- `readonly holdProgress = output<number>()` — эмитит текущий прогресс (от `0` до `100`);
- `readonly holdTimeEnd = output<void>()` — эмитит событие, когда пользователь удержал кнопку до конца.

## Пошаговое задание

### Шаг 1. Соберите потоки начала и отмены удержания

Внутри `HoldableDirective` получите нативный DOM-элемент кнопки (`this.el.nativeElement`) и создайте два потока событий через `fromEvent`:

1. **Поток старта (`start$`):** срабатывает при нажатии на кнопку (`pointerdown` или `mousedown`).
2. **Поток отмены (`cancel$`):** объединяет (`merge`) все события, которые должны прерывать удержание:
   - отпускание кнопки (`pointerup` / `mouseup`);
   - уход курсора за пределы кнопки (`pointerleave` / `mouseleave`);
   - системная отмена жеста (`pointercancel`).

---

### Шаг 2. Запустите таймер прогресса с отменой

Свяжите `start$` с внутренним таймером:

1. На каждое событие `start$` запускайте внутренний поток `interval(stepMs)` (например, каждые `10` или `20` мс) с помощью оператора высшего порядка, который **перезапускает** таймер при новом нажатии.
2. Переводите номер тика в процент выполнения: от `0` до `100` в зависимости от `this.holdTime()`.
3. Ограничьте внутренний поток так, чтобы он:
   - автоматически останавливался при событии из `cancel$`;
   - при отмене сбрасывал прогресс обратно в `0` (чтобы полоса `<progress>` на экране не застревала на середине!).
4. Передавайте вычисленный процент в `this.holdProgress.emit(...)`.

---

### Шаг 3. Зафиксируйте успешное завершение (`holdTimeEnd`)

Когда прогресс доходит до `100%` (время удержания достигло `this.holdTime()`):

1. Внутренний поток таймера должен остановиться (чтобы процент не рос выше `100%` и событие не стреляло многократно, пока палец ещё лежит на кнопке).
2. Ровно один раз за удержание должен вызваться `this.holdTimeEnd.emit()`, после чего в `AppComponent` сработает `onSend()`, в консоль выведется `'Save it!'`, а счётчик на карточке увеличится на `1`.
3. Не забудьте привязать жизненный цикл подписки к уничтожению директивы (`takeUntilDestroyed()`).

---

### Шаг 4 (`*`). Плавное «остывание» прогресс-бара вместо мгновенного сброса

В базовом варианте при отпускании кнопки на `60%` полоса мгновенно прыгает в `0%`.
Попробуйте сделать так (в качестве дополнительного эксперимента), чтобы при раннем отпускании кнопки полоса не обнулялась мгновенно, а быстро «таять» назад к нулю, либо добавьте поддержку удержания клавиши `Space` / `Enter` с клавиатуры (при этом учитывайте, что зажатая клавиша генерирует повторяющиеся события `keydown` с `event.repeat === true`).

## Ограничения

- Не используйте `setTimeout`, `setInterval` и `requestAnimationFrame` напрямую — вся работа со временем должна идти через потоки RxJS.
- Директива должна оставаться переиспользуемой: не привязывайте её жёстко к `2000 мс`, используйте значение из `this.holdTime()`.

## Как проверить решение

### 1. Сценарий ручной проверки в браузере (Чек-лист)

- [ ] Зажмите кнопку **Hold me** — полоса прогресса плавно движется от `0%` к `100%`.
- [ ] Отпустите кнопку на половине пути — полоса возвращается в `0%`, счётчик `Выполнено` остаётся `0`.
- [ ] Снова зажмите кнопку и уведите курсор мыши в сторону, не отпуская кнопку — отсчёт отменяется, полоса сбрасывается в `0%`.
- [ ] Зажмите кнопку и держите полные 2 секунды — полоса доходит до `100%`, в консоли появляется `'Save it!'`, плашка внизу зеленеет, а счётчик `Выполнено` увеличивается на `1`.
- [ ] Продолжайте держать кнопку ещё пару секунд после срабатывания — повторных вызовов `'Save it!'` без нового нажатия не происходит.

## Подсказки

<details>
  <summary>💡 Подсказка 1 — Какой оператор высшего порядка выбрать для запуска таймера?</summary>

При каждом `pointerdown` нам нужно начать новый отсчёт с нуля, отменив предыдущий (если он почему-то ещё шёл). Это классическая задача для `switchMap`:

```ts
start$.pipe(
  switchMap(() => interval(20).pipe(
    // ...логика расчёта процента, завершения и отмены
  ))
)
```
</details>

<details>
  <summary>💡 Подсказка 2 — Как остановить таймер на 100%?</summary>

Оператор `interval(step)` бесконечен: он выдаёт `0, 1, 2, 3...`.
Если перевести тик в прошедшее время `elapsed = (tick + 1) * step`, то процент равен `Math.min(100, (elapsed / this.holdTime()) * 100)`.
Чтобы поток сам завершился при достижении `100`, используйте `takeWhile((percent) => percent <= 100, true)` (второй аргумент `inclusive: true` позволяет пропустить само значение `100` перед завершением) или `take(...)`.
</details>

<details>
  <summary>💡 Подсказка 3 — Как сбросить прогресс в 0 при раннем отпускании?</summary>

Есть два удобных способа:
1. Подписаться или добавить `tap(() => this.holdProgress.emit(0))` в поток `cancel$`.
2. Либо внутри `switchMap` объединить поток таймера с потоком отмены так, чтобы отмена эмитила `0` и завершала внутренний поток (например, `takeUntil(cancel$.pipe(tap(() => this.holdProgress.emit(0))))`).
</details>
